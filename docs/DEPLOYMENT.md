# Deployment (Staging on Render)

## How it works
- Every PR runs CI (`.github/workflows/ci.yml`): build, test, and Docker image build.
- Merging to `main` auto-deploys to Render using `render.yaml`.

## One-time setup (Zed)
1. In GitHub: Settings > Branches > add a rule for `main`:
   - Require a pull request before merging (1 approval)
   - Require status checks: "Build & Test" and "Docker images build"
2. In Render: New > Blueprint > connect the repo > it reads `render.yaml`.
3. When prompted, leave `Api__BaseUrl` and `Cors__AllowedOrigin` blank on first run.
4. After the first deploy, copy each service's public URL:
   - doggodex-web > Environment > `Api__BaseUrl` = API URL
   - doggodex-api > Environment > `Cors__AllowedOrigin` = Web URL
5. Check `<api-url>/health` returns Healthy.

## Secrets
- Never commit secrets. They live only in Render environment variables.
- `Jwt__Key` is auto-generated by Render.
- The database connection string is injected by Render from `doggodex-db`.

## Free tier notes
- Free web services sleep when idle, so the first request after a pause is slow.
- Free Render databases expire after a limited time. Check the current limit
  and keep a calendar reminder before the course demo.
